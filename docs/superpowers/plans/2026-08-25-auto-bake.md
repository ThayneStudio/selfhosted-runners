# Auto-bake and maintain timer Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking. REQUIRED: superpowers:test-driven-development — no production code without a failing test first.

**Goal:** Unattended template bake that never destroys the active clone target, driven by input digest change plus a weekly floor, so `--disableupdate` can ship on `pve` without a human rebake.

**Architecture:** Keep `TEMPLATE_ID` as the active-generation pointer. New bakes allocate a VMID from 8900–8999, write a generation record (`baking` → `candidate` or `failed`), and leave the live fleet on the previous template. `runner maintain` (daily 02:30 timer) runs adoption → reconcile dead `baking` records → detect → bake. Promotion is a separate verb (`runner promote --skip-canary`) so a candidate can become the clone target without the canary stack; `clone_runner` re-reads `TEMPLATE_ID` after taking the pool lock so a promotion takes effect on the next clone.

**Tech Stack:** bash, `qm`/`pvesm`/`pvesh`, systemd timers, bats-core unit tests with the existing stub harness, shellcheck, yamllint.

**Spec:** `docs/specs/2026-08-22-generational-runner-platform.md` (authoritative). Issue graph: #13, #14, #15 (plus comments), #23, #24. Carried-forward comments on #15 are in-scope.

## Global Constraints

- Host paths are constants in `lib/common.sh`, never literals in other `lib/*.sh` (enforced by `tests/unit/common_path_constants.bats`; spec §16, §21).
- One persistent-state root: `RUNNER_STATE_DIR` (`/var/lib/github-runners`), created only via `ensure_state_dir` at mode 700.
- Defaults live in `apply_generation_defaults()` via `${VAR:-default}`. Do not append the spec §14 keys to `/etc/github-runners.conf` on install.
- Enforcement fails closed. `|| true` / `2>/dev/null` is for notify and leftover cleanup only — never for checksums, destroys, promotions, or digest memos.
- A comment that claims never/always/cannot names the test that proves it, or is written `ASSUMPTION:`.
- Do not parallelize tasks that share a file. This plan is strictly sequential. Shared files: `lib/common.sh`, `runner`, `lib/setup.sh`, `install.sh`.
- Checksum verification must fail closed even when the download helper is invoked as `if ! bake_download_image; then` — wrapping a function in a checked context suppresses `set -e` for its body (#15 comment 1). Use explicit `return` after every status check; never rely on a bare assignment aborting.
- `notify <severity> <event> <message> [detail]` never fails the caller. Bake events: `bake.started`, `bake.failed`. Promote: `generation.promoted`. Optional `NOTIFY_GENERATION=<uint>` for the JSON `generation` field.
- Generation store API (already shipped, do not reimplement): `gen_create`, `gen_read`, `gen_update`, `gen_transition`, `gen_list`, `gen_state_of`, `gen_vmid_for_id`, `gen_remove`, `gen_archive_append`, `gen_next_id`. `gen_create <vmid> [KEY=VALUE ...]` defaults `GEN_STATE=baking`. Identity fields are immutable after create. `gen_transition` is idempotent (already-in-state returns 0).
- Unit tests use `load test_helper` + `load_lib <file>` + `write_infra_config` + `stub_out`. Do not stub `flock`. Destructive `qm destroy`/`qm stop`/`pvesm free`/`zfs destroy` require an explicit stub rule. `tests/run.sh` is the gate: `./tests/run.sh`.
- CLI libraries that `require_root` / `load_infra_config` at source time cannot be `load_lib`'d from bats. Split: `lib/bake.sh` is a library of functions; `runner bake` is a thin dispatcher that sources it and calls `bake_main "$@"`. Same pattern for detect/promote/maintain. Tests `load_lib bake.sh` after the library no longer has a main-at-source side effect.
- Production target is `pve`, not `pve-test` (orcest). Tests never SSH anywhere.
- Out of this plan (later issues): canary orchestration (#21/#22), full GC (#18), drift alarm (#12 — not actually shipped despite #23's body), `runner status`/`generations` (#16), rollover (#20), README rewrite (#25).

## Scope rulings (binding)

1. **`runner bake` always allocates from the band and always ends `candidate`.** It never writes `TEMPLATE_ID` and never converts VM 9000. The active fleet is untouched on success and on failure.
2. **Bootstrap of a brand-new host** (no template at `TEMPLATE_ID`, empty generation store): `runner setup` writes config, calls bake, then promotes the candidate with skip-canary and no extra prompt (setup is already interactive). Production `pve` never takes this path — 9000 already exists and is adopted.
3. **Adoption** of an existing `TEMPLATE_ID` template is a no-op second run, never destroys, records `GEN_TEMPLATE_DIGEST=unknown` and `GEN_IMAGE_SHA256=unknown`. An `unknown` digest never matches, so the first detect after adoption requests a bake.
4. **`CANARY_ENABLED` defaults false.** `runner maintain` does **not** auto-promote. After an unattended bake the operator runs `runner promote <id> --skip-canary` (interactive confirm). That is enough to roll out `--disableupdate` once a candidate exists.
5. **`/opt/.runner-version`:** write it from `templates/template-setup.yaml` next to the existing `RUNNER_VERSION` fetch, immediately before the completion marker. That is a one-time digest change and is intended. The generation stamp (`/etc/github-runner/generation`) is **not** in that yaml; bake writes it with `qm guest exec` after the marker is observed and before shutdown (#15 comment 2).
6. **Older unused candidates:** after a successful bake, `maintain` (and `runner bake` itself) transitions any other `candidate` to `failed` with reason `superseded by newer candidate` and `qm destroy --purge`s it. This is the leak-prevention slice of spec §9, not full GC.

```bash
validate_generation_band() {
    local min_vmid="${MIN_VMID:-0}"
    local band_min="${TEMPLATE_BAND_MIN}"
    local band_max="${TEMPLATE_BAND_MAX}"

    if [[ ! "$band_min" =~ ^[0-9]+$ || ! "$band_max" =~ ^[0-9]+$ ]]; then
        log_error "TEMPLATE_BAND_MIN/MAX must be unsigned integers (got ${band_min:-<empty>}, ${band_max:-<empty>})"
        return 1
    fi
    if [[ "$band_min" -gt "$band_max" ]]; then
        log_error "TEMPLATE_BAND_MIN ($band_min) is greater than TEMPLATE_BAND_MAX ($band_max)"
        return 1
    fi
    if [[ "$min_vmid" -eq 0 ]]; then
        log_error "MIN_VMID=0 (auto) is incompatible with generations; set MIN_VMID to $((band_max + 1)) or higher"
        return 1
    fi
    if [[ "$band_max" -ge "$min_vmid" ]]; then
        log_error "Generation VMID band ${band_min}-${band_max} overlaps [MIN_VMID, ∞) (MIN_VMID=${min_vmid})"
        return 1
    fi
    return 0
}
```

Call it at the end of `load_infra_config`. Foreign-config-in-band check (a VM config in the band that is not a generation record) lands in Task 2 — it needs `qm`/`gen_exists`.

**Files:**

Prefer extract now so the awk-extract tests die and the real function is tested. setup.sh's bake branch then calls the function for download; VM create stays until Task 5.

**Interfaces:**
- Consumes: `CLOUD_IMG*`, `MIN_CLOUD_IMG_BYTES`, `IMG_CACHE_DIR`, `FAILED_DIGESTS_FILE`, `DOCKER_MIRROR_URL`, `VM_STORAGE`, `NETWORK_BRIDGE`, `VLAN_TAG`, `DNS_SERVERS`, `BALLOON`, `INSTALL_DIR`
- Produces:
  - `render_template_setup` → stdout rendered yaml (DOCKER_MIRROR_URL substitution, same awk as setup.sh:496)
  - `fetch_latest_runner_version` → stdout version without `v`; exit 1 on failure (no silent empty)
  - `fetch_image_checksum_entry` → stdout the SHA256SUMS line for `$CLOUD_IMG`; exit 1 on fetch/parse failure
  - `compute_template_digest` → stdout hex sha256; concatenates in this exact order, each followed by a newline:
    1. rendered yaml
    2. runner version string
    3. SHA256SUMS entry line
    4. `DOCKER_MIRROR_URL=${DOCKER_MIRROR_URL}`
    5. `VM_STORAGE=${VM_STORAGE}`
    6. `NETWORK_BRIDGE=${NETWORK_BRIDGE}`
    7. `VLAN_TAG=${VLAN_TAG}`
    8. `DNS_SERVERS=${DNS_SERVERS}`
    9. `BALLOON=${BALLOON}`
  - `digest_is_memoed <digest>` → 0 yes, 1 no
  - `memo_failed_digest <digest>` → append unique line, mode 600, via `ensure_state_dir`
  - `bake_download_image` → 0 verified cache at `CLOUD_IMG_PATH`; 1 fail. **Fail closed on SUMS fetch.** Explicit `return 1` after every failed command. When invoked from `if ! bake_download_image`, a failed `EXPECTED_SHA256=$(…)` must still `return 1` — check `wget` status before using the body.

Digest of `unknown` is a stored sentinel, never the output of `compute_template_digest`. Comparison: if active `GEN_TEMPLATE_DIGEST` is `unknown` or empty, detect reports "bake needed (unknown digest)".
